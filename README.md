# Uncertainty-Aware Trajectory-to-Beam and Predictive ADB Control

Research code for a WOMD-based trajectory-to-control pipeline. The main path
preserves the project's original research-oriented design:

```text
WOMD oracle/clean actor histories
  -> probabilistic trajectory prediction (Stage 4)
  -> adaptive Top-K beam selection (Stage 5)
  -> predictive class-aware ADB (Stage 6)
  -> shared-posterior joint evaluation (Stage 7)
```

Stages 0-3 contain the optional sensing-conditioned path (coordinate audit,
WOMD-LiDAR features, physics-based PC-FMCW-like observations and classical
tracking baselines). They are retained for clean-vs-noisy ablations, but are
not required to reproduce the primary Stage 4-7 pipeline.

## Scientific scope

- WOMD provides real actor trajectories, interactions, map context and ego
  motion.
- WOMD-LiDAR provides real scene geometry and non-FMCW LiDAR context.
- WOMD-LiDAR does **not** provide measured FMCW Doppler. Any PC-FMCW
  observation in Stages 0-3 is physics-based simulation.
- The primary Stage 4-7 results use causal clean/oracle actor histories; future
  states are labels only.
- ADB references are geometry-based constructed oracles, because WOMD has no
  ADB ground truth.
- Reported latency sweeps model stale posterior information, not physical
  headlamp actuator latency.

## Main reported operating point

The frozen Stage-7 report evaluates a 64-beam codebook with target posterior
mass 0.95. On 47 connected-vehicle receivers it reports mean posterior coverage
0.9970 (95% bootstrap CI 0.9955-0.9983), mean selected beam-set size 1.8447,
and mean probing overhead 0.0288. On the 167-actor joint cohort, the
constructed-oracle ADB evaluation reports mean mask IoU 0.8411, mean shadow-zone
violation 0.00944, over-masking 0.00579, and road-illumination retention 0.9634.

These are archived experimental outputs, not automatically regenerated by a
unit-test run. See `paper/CLAIM_EVIDENCE.md` for the exact evidence and the
remaining publication gates.

## Environment

Python 3.10+ is recommended:

```bash
python -m venv .venv
. .venv/bin/activate
python -m pip install -e '.[dev]'
```

WOMD/WOMD-LiDAR execution additionally requires the Waymo Open Dataset stack
and access to data obtained under the Waymo Dataset License Agreement. Raw
Waymo data and model checkpoints are intentionally not distributed here.

## Tests

```bash
pytest -q
```

Tests requiring local WOMD data should be skipped when `WOMD_ROOT` is not
configured. Archived JSON reports allow paper claims to be audited without
redistributing the dataset.

## Reproducibility policy

1. Keep training, calibration and evaluation splits disjoint.
2. Never expose future states to a predictor input.
3. Report clean/oracle and sensing-conditioned results separately.
4. Fit calibration parameters on validation data only.
5. Freeze controller hyperparameters before final evaluation.
6. Use actor-level bootstrap confidence intervals for joint metrics.

## Paper status

`paper/manuscript.tex` is aligned with the implemented Stage 4-7 pipeline. Its
numerical results are preliminary until the corrected classical baselines and
their downstream comparisons are regenerated as described in
`paper/CLAIM_EVIDENCE.md`.
